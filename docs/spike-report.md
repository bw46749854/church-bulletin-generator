# 段1 スパイク報告 — 2026-07-19 の再現（2026-09-14）

## 目的
原本（Word→PDF）と同じ紙面を、JSON＋HTML/CSS＋Chromium で再現できるか。フォント置換の影響を見る。

## 方法
1. 原本 PDF から枠線（細い塗り矩形）と文字行の座標・サイズを実測（mm）。枠の座標は 0.1mm 単位でテンプレに転記。
2. 原本の文言を week.json / config.json / マスタに分解。
3. テンプレを Playwright（Chromium 153, headless shell）で PDF 化。
4. 検証：
   - 文字列照合：原本の全 338 行（正規化後）が生成 PDF に含まれるか。欠落があればクリップの疑い。
   - 画像比較：110dpi で重ね合わせ（原本＝赤／生成＝青／一致＝黒）。

## 結果
- 枠線位置：原本と一致（重ね合わせで黒）。式順の行位置も一致。
- 文字列照合：欠落 2 行のみ。いずれも意図した差（午後礼拝が休みの週は右列を空にする＝牧師回答 P3／中高科の「休会」の置き位置）。
- 溢れ：fit-policy 適用後、溢れなし（両フォント）。
- フォント：
  - IPAex明朝（既定候補）：MS P明朝に近い印象。かなが MS P明朝より広いため、賛美曲名（15字）と説教題は倍率 0.8〜0.85 に条件付き縮小。原本も倍率で収めていた箇所。
  - BIZ UDP明朝：字面が大きく太く見え、「変わった」と気づかれやすい。UD の可読性は高い。
- 相違として残るもの：使徒信条・覚えて祈りましょうの折り返し位置（かな幅の差）、報告の折り返し位置。紙面配分は同じ。

## 分かったこと・決めたこと
- 既定フォントは IPAex明朝／IPAexゴシック（IPA フォントライセンス v1.0、同梱可）。BIZ UD は `SHUHO_FONT=biz` で切替可。牧師に両方見せて決める（要件定義 P8）。
- 縮小は「倍率 → 文字サイズ」の順（原本の慣行に合わせた）。
- 右列が空の行（聖書のページ行）は右列を省略して内容欄を広げる。
- 文字列照合は「クリップ検出」として有効。今後もテンプレ変更時に回す。

## 環境メモ
- Ubuntu 26.04 (WSL2) は Playwright 1.63 の対応外 OS だが、Chromium headless shell は動く。不足ライブラリ（libnspr4, libnss3, libasound2）を sudo なしで `.local-libs` に展開し `LD_LIBRARY_PATH` で渡した。恒久対応は `sudo apt install libnspr4 libnss3 libasound2t64`。
- Node v24（nvm）、Python は scratchpad の venv（pymupdf, openpyxl, pillow）。
