# ファイルの置き場の設計（版を持つ置き場）

**状態: 本番に反映済み（2026-10-25 12:08 日本時間、main 5a2155b）。** 移行（§4 の 1）は同日 9:40 に済み、反映の直前にもう一度流して一致を確かめた。古い名前の KV のキーの削除（§4 の 4）はまだ（戻すときの備えに、しばらく残す）。 ARCHITECTURE.md §2.1・§2.2・§2.6 はこの形で書き直した。

## 0. なぜ作り直すか

ファイル（歌詞・交読文・テンプレの pptx と、テンプレの JSON）は Workers KV に置いている。KV は**書いた内容が世界中の拠点に行き渡るまで最大 1 分ほどかかる**（拠点が古いコピーを持っていることがある。ファイルの一覧も同じ）。
いまの設計は「同じ名前（`hymns/48.pptx`・`template/部品/賛美.pptx`）のまま中身を上書きする」で、中身の指紋（sha256）は中身に付けた付箋（KV のメタデータ）として持つ。古いコピーには古い付箋が付いてくるので、**書いた直後に読むと、古い中身を新しいと思い込んで使うことがある**。

業務で起きること（どれも変えてから 1 分ほどの間）:

| 場面 | いま起きること |
|---|---|
| ファイルを消した直後の管理画面 | 一覧に残る（2026-10-24 0:22 に verse-spTree.xml で実際に起きた） |
| 部品や歌詞を差し替えて、すぐスライドを作る | **古い部品・古い歌詞のまま黙って作られる**ことがある（「直して、すぐ作って確かめる」はいちばんよくある使い方） |
| 家の担当者が色を変え、直後に教会で牧師が作る | 前の色で出る |
| 2 人がほぼ同時に歌詞の pptx を上げる | 一覧表 `manifest.json`（読んで直して書く）の片方の記録が落ち、置いてあるのに「pptx 未登録」と出る |

あわせて、前の中身の控え（KV の `history/`）は増える一方で、消す仕組みが無い（D1 の `history/` も同じ）。

条件: 支払い方法（カード）は登録しない（R2 は使えない）。Worker の計算時間は 1 回 10ms まで。D1 は 1 行 2MB まで。

## 1. 形

| 置き場 | 名前 | 中身 | 書き換え |
|---|---|---|---|
| KV | `blobs/<sha256>` | ファイルの中身（pptx・JSON） | **しない**（一度置いたら変わらない。同じ中身は 1 つを共有） |
| D1 | `index/<ファイルの名前>.json`（例 `index/hymns/48.pptx.json`、`index/template/部品/賛美.pptx.json`） | 目次の行: `{"sha256", "size", "uploaded", "source", "modified", "slides", "ratio"}`（後ろの 3 つは歌詞・交読文だけ。`source` は元のファイル名で、分からなければ `null`） | 差し替え・削除のたび |

- **今の版を決めるのは D1 の目次の行だけ。** D1 は書いた瞬間から、どこから読んでも最新を答える。
- ファイルの名前（`hymns/48.pptx` など）とキーの決まり（`src/lib/file-keys.mjs`）・API のパス（`api/files/<名前>`）は今のまま。画面と担当者の窓口は変えない。
- 目次は 1 ファイル 1 行（全部を 1 つの JSON にすると、同時に書いたとき片方が落ちる）。いまの `manifest.json` の中身（元のファイル名・更新日・枚数・比率）はこの行に入り、`manifest.json` は無くなる。
- 目次の名前を `index/…` にするのは、手元（開発サーバ・recovery）で D1 の行が `data/<名前>` のファイルになるため（`data/files/` の pptx とぶつからないように）。

## 2. 動き

| 操作 | すること |
|---|---|
| **読む**（スライドを作る・ダウンロード） | D1 の目次の行 → 指紋 → KV の `blobs/<指紋>`。KV に無ければ（置いた直後でまだ届いていない）1 秒あけて読み直す（最大 5 回）。目次に行が無ければ「ありません」（404）。古い中身を掴むことは起きない（版の名前と中身が必ず一致する） |
| **置く・差し替える** | 届いた中身の指紋を確かめる → KV に `blobs/<指紋>` を置く（すでにあれば置かない）→ 目次の行を書く。**書いた瞬間から全員が新しい版を使う**（下書きは挟まない。2026-10-25 ユーザー決定） |
| **消す** | 目次の行を消す。その瞬間から、どの画面にも出ない。KV の中身は消さない（控えが指している。§3 の片付けで消える） |
| **一覧**（管理画面のテンプレ、讃頌歌・交読文の「pptx 未登録」、同期） | D1 の `index/` の行。書いた直後から正しい |
| **ETag**（ブラウザの「前と同じ？」） | 目次の行の指紋 |
| **戻す** | 控え（§3）の行を、今の行に書き戻す（中身が KV に残っている 14 日の間）。画面は後で作る |

- 目次の行を書くのは、今の共通部品 `writeObject`（`src/lib/api.mjs`）。**前の行は自動で D1 の `history/` に残り、変更の記録（ARCHITECTURE.md §2.6）が付く**。ファイル専用の `writeFile`（KV の `history/` に写す）は無くなる。
- 古い中身を KV の `history/` に写し直すことはしない（同じ中身が 2 つになり、書き込みも増えるだけ）。「控えの行が古い中身を指している」形が、ファイルの控えになる。

## 3. 控えと片付け（14 日。2026-10-25 ユーザー決定）

- 控えは D1 の `history/<名前>/<時刻>`（`writeObject` が作る。マスタ・教会情報などの JSON の控えも同じ）。週データの保存は控えを作らない（今と同じ）。
- **毎日 日本時間 3:00 に、Worker の定時実行（Cron Triggers、`wrangler.jsonc` の `"triggers": {"crons": ["0 18 * * *"]}`、`worker/index.mjs` に `scheduled` を足す）で片付ける**:
  1. 時刻が 14 日より古い `history/` の行を探す（1 回 40 件まで。無料の D1 は 1 回の呼び出しで問い合わせが 50 回まで。残りは翌日）
  2. 目次の控えなら、指していた指紋を覚える
  3. その行を消す
  4. 覚えた指紋の中身を、今の目次の行も残っている控えも使っていなければ、KV から消す
  5. 結果（いつ・控え何件・中身何件）を D1 の `meta/cleanup/last.json` に書き、Workers Logs にも出す。管理画面のテンプレの欄に「最後の片付け」を出す
- 何度動いても結果が同じになる作り（失敗しても、その場ではやり直さず、翌日に追いつく）。時刻は数分ずれることがある。preview の版では定時実行は動かない。
- 片付けた後は、その版には戻せない。変更の記録（いつ・誰が・どの指紋に）は残る。長く取っておきたいテンプレは、管理画面の「テンプレ一式をダウンロード（zip）」で手元に置く。
- 量: 無料の KV は 1GB・消すのは 1 日 1,000 回まで。この教会の変更の頻度なら十分に収まる。

## 4. 移行

台本は `scripts/migrate-files.mjs`（本番は `--remote`、手元は `--local`）。何度流しても同じ結果になる（すでにある中身は置かない。目次の行は、古い置き場の方が新しいときだけ書き換える）。

1. **移す**（新しいコードを入れる前。いまのコードは `index/`・`blobs/` を読まないので影響しない）: `node scripts/migrate-files.mjs --remote --dry-run` で数を確かめてから `--dry-run` を外す。
   KV の今のファイル（歌詞 259・交読文 64・テンプレ 29。2026-10-25 時点）の中身を `blobs/<指紋>` に置き、D1 に目次の行を作る（`manifest.json` の元のファイル名・更新日・枚数・比率を行に入れる。テンプレの元のファイル名は分からないので `null`）。
   KV の `history/` の写し（9 個。すべて 14 日以内）は `blobs/` と D1 の控えの行に移す（元の時刻のまま。14 日たてば片付けで消える。今は使わない名前 `template/worship.pptx` などの控えも同じ）。
   置く中身は 358 個（40.7MB。KV の書き込み 358 回で、無料の 1 日 1,000 回に収まる）。変更の記録に `op: "migrate"`・`via: "wrangler"` で 1 ファイル 1 件残す。最後に、目次と控えの行が指す中身がすべて KV にあるかを確かめる。
   中身は、手元の `data/files` に同じ指紋のものがあればそれを使い、無ければ KV から取る。
2. **新しいコードを main に反映**（読む・書く・一覧を目次経由に、定時実行を足す）。
3. 本番で 4 エリアのスライド作成・管理画面・讃頌歌の pptx の上げ下ろしを確かめる。
4. 古い名前の KV のキー（`hymns/…`・`readings/…`・`template/…`・`manifest.json`・`history/…`）を消す: `node scripts/migrate-files.mjs --remote --drop-old`。今の名前のキーがどれも目次に行を持ち、目次と控えが指す中身がすべて `blobs/` にあるときだけ消す（362 回。消すのも無料で 1 日 1,000 回まで）。
- 1 と 2 の間に担当者がファイルを置くと取りこぼすので、担当者がスライドを作らない時間（平日の昼など）に行う。取りこぼしても、2 の直前に 1 をもう一度流せば拾える。
- 2 を戻す（main を前の版に戻す）と、古いコードは古い名前のキーを読む。反映の後に置いたファイルは古い名前には無いので、戻すなら 4 の前に、その間に置いたファイルを置き直す。
- 手元（開発 PC の `data/files`）は `--local` で同じことをする（2026-10-25 に済み。古い `data/files/hymns/` などは `--local --drop-old` で消す）。

## 5. 変えたところ（コード）

- `src/lib/file-store.mjs`（新設）: 目次の行を読む・中身を読む（読み直し）・置く・消す・一覧・片付け。目次の行を書く・消すのは API の共通部品 `writeObject`・`removeObject`（`src/lib/api.mjs`）。
- `src/lib/api.mjs`: ファイルを読む・置く・消す・一覧を目次経由に。`writeFile`・`setManifest`・`readManifest` を消し、`api/bootstrap` の `files`（pptx の有無）も目次から作る（画面に渡す形は今と同じ）。`GET api/files/blobs/<指紋>`（写し・同期用）を足した。`GET api/templates` は最後の片付け（`cleanup`）も返す。
- `src/lib/store-d1.mjs`・`src/lib/store-fs.mjs`: `scan`（prefix の下の行を本文つきで。時刻より前・件数の上限）と `removeMany`（まとめて消す）。手元の中身の置き場 `fsFiles`（`data/files/blobs/`）。
- `worker/index.mjs`・`wrangler.jsonc`: 定時実行（`scheduled`、`"triggers": {"crons": ["0 18 * * *"]}`）。KV の置き場の部品 `kvFiles(env)` を API と片付けで共用。
- 手元: `scripts/dev-server.mjs`（recovery も）・`scripts/make-slides.mjs` が目次経由で読む。`scripts/pull.mjs` は目次を JSON と一緒に、中身を `blobs/` で写す。`scripts/seed-kv.mjs` は `data/files/blobs` の中身だけを KV に置く（目次は `seed-d1`）。
- 画面: テンプレの管理画面に控えの残し方と最後の片付けを出す。使わなくなったテンプレ（`worship.pptx` など）を出す欄は消した（移行で移さない）。
- 試験: `tests/file-store.test.mjs`（目次経由の読み書き、同じ中身の共有、消す、読み直し、片付け: 14 日・共有している中身は消さない・件数で区切る）、`tests/store-scan.test.mjs`、`tests/template-files.test.mjs`。

## 6. 決めたこと（2026-10-25）

- 中身は KV に指紋の名前で置き、上書きしない。今の版の目次は D1 の 1 ファイル 1 行（ユーザーの確認済み）。
- 差し替えはすぐ反映（下書き → 公開の流れは採らない。修正の手間を減らすため。ユーザー決定）。
- 控えは今の共通部品（`writeObject`）で D1 の `history/` に残す。14 日で、毎朝 3:00 の定時実行で片付ける（ユーザー決定）。
- 採らないもの: R2（カードの登録が必要）、全部 D1 に置く（1 行 2MB までで大きい歌詞を分けることになり、組み立てる計算で 10ms を超えるおそれ）、「1 分お待ちください」と出すだけ（古いもので作られる誤りを防げない）。

## 7. 確かめたこと・残っていること

- 無料プランの上限（2026-10-25 に Cloudflare の文書で確かめた）: 定時実行はアカウントで 5 つまで（使うのはこの 1 つ）。1 回の呼び出しの計算時間は 10ms、D1 の問い合わせは 50 回まで（片付けはまとめて消すので 1 回あたり数回）、KV などへの呼び出しは 1,000 回まで（片付けは 40 件で区切る）。
- KV の読み直しは 1 秒おき最大 5 回にした。
- 残り: 移行の日時（ユーザーと決める）。「戻す」の画面を作るか（作るなら、管理画面のファイルごとに「前の版に戻す」）。
