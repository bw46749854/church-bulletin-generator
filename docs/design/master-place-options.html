マスタの置き場所 — 3 つの案

2026-10-24。今の「マスタ」タブは、週の選択（ヘッダ）の下に、週の欄と同じ並びで置かれている。そのため「選んだ週の中のマスタ」に見えるが、実際の操作は週データ（weeks/<日付>.json）に書かず、どの週にも共通の台帳（D1 の masters/・KV の pptx）をその場で書き換える。
決めたこと（10/24、ユーザーと合意）: マスタを週の欄から外し、見出し（ヘッダ）の高さで「週報」と並べる。別ページにはしない（週の入力中に「曲名が未登録」→ 登録 → 戻る、の行き来で、未保存の入力を残したまま題がその場で入るように）。

  • 3 案とも共通: マスタを開いている間は、週の選択・保存の状態・保存・サイトに反映を出さない。代わりに「どの週にも共通。変更は確かめた後すぐに反映され、保存は要らない」と出す。
  • 週の欄に「マスタ」タブは無くなる（主日礼拝／午後・水曜・次週／報告・表紙／スライド／（同期）／プレビュー）。
  • マスタの中身は今のマスタタブのまま（讃頌歌・交読文／名簿／控えを取る／ファイルの差し替え）。開発者向けの「システム」欄（PDF エンジンの版・今日の生成回数）はマスタではないので「…」の中へ。
  • 同じ週が別のタブで編集中のときの覆い（待機画面）は週報の側だけに掛ける。マスタは待たずに使える。
  • 担当者ページ（スライド担当）も同じ形にそろえる（同じ部品 src/ui/masters.mjs を使っているため）。

状態の例は「週報に未保存の変更があるまま、マスタを開いた」。各案を 1024px（iPad 横・小さめの PC）と 768px（iPad 縦）で示す。

理由: 牧師にとってマスタは「週の入力中にときどき行って、すぐ戻る」場所で、担当者にとってはスライドと並ぶ主な仕事。どちらにも合うのは、2 つが対等に並び、同じ場所を押せば行き来できる A。 A は「週報｜マスタ」が週の選択より左（＝上の階層）にあるので、マスタが週の中にあるとは読めない。見出しは 1 段・56px のままで、10/11 に決めたヘッダ（週が主役）の形も崩さない。 B は別の場所にいることが一番はっきりするが、行きと帰りのボタンの位置が違い、768px では「保存」の隣に別の行き先が並ぶ。C は上下関係が最も正確だが、毎週使う入力欄の高さを削ってまで得るものが少ない。

A の細かいところ

  • マスタを開いている間は、週の選択・保存の状態・「保存」・「サイトに反映…」を出さない。代わりに「どの週にも共通。変更は確かめた後すぐに反映されます（「保存」は要りません）」。
  • 週報に未保存の変更があるときは、マスタの間も「週報」の横に黄色の点（保存の状態の点と同じ色）。週報に戻ると、入力はそのまま残っている。
  • どちらを開いているかは URL の末尾（#masters）にも出す。読み込み直しても同じ側が開き、ブラウザの「戻る」で週報に戻れる。
  • 週の欄の「曲名が未登録（『マスタ』タブで登録）」は「曲名が未登録 — マスタで登録」のリンクにし、押すとマスタの「新規」に番号が入った状態で開く。
  • 768px では日付の年を省く（「10月25日（日）」）。週の一覧の中は今どおり年つき。
  • 担当者ページ: 見出しを「（スライド担当）［週報｜マスタ］ 週［選択］ … ログイン中」にし、マスタを開いている間は週の選択を出さない。週報の側のタブは「スライド」「週報（PDF）」。
  • 「…」の中: フォント（評価用）／サイトに出ている週／PDF エンジンの版・今日の生成回数（今の「システム」欄）／ログイン中のアカウントとログアウト。
