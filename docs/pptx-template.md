# 礼拝スライドの生成の設計（背景・部品・式順）

**状態: 実装済み（2026-10-25、ブランチ `gen-1`。本番は未反映）。** ARCHITECTURE.md §18・§14.9 と docs/OPERATIONS.md はこの文書を指す。本番で 4 エリアとも作って確かめたら「本番」にし、使わなくなった `template/worship.pptx`・`template/verse-spTree.xml` を消して、`src/lib/file-keys.mjs` の決まりからも外す。

## 0. なぜ作り直すか

これまでは、1 つのテンプレ（`template/worship.pptx`）の**過去の実物の文字**（「2025年 MM月YY日」「A牧師」「9.  ご年配…」「マタイ6:19-21」など）と、見出し・並び（「説教」で始まるスライド、献金の次のスライド、文字の無いスライド＝歌詞の空き）を目印にしていた。午後・水曜・その他も同じテンプレから「最初の空きスライド」と「説教」のスライドを借り、並びはコードに書いてあった。
そのため、テンプレの普通の編集で生成が黙って壊れ（2026-10-24 に実際に起きた）、どこを直すと何に効くかが見えなかった。

方針（2026-10-24 決定）:
- **テンプレ（pptx・JSON）は常にこの約束どおりの最新の状態を前提にする。** コードは古いテンプレのための代わりの動きを持たない。約束どおりでなければ知らせる。
- **直すときの影響範囲が、直したものだけに閉じるように分ける。** 見た目の共通部分（背景）、1 つ 1 つの部品、礼拝ごとの並び（式順）、値の作り方（コード）を、それぞれ別の所に置く。

## 1. 全体の形

### 1.1 置くもの（名前は `template/…`。中身は KV の `blobs/<指紋>`、今の版は D1 の目次 `index/template/…`（`docs/file-store.md`）。どれも別ファイルで、差し替え・記録・控えもファイルごと）

| ファイル | 中身 | 直すと影響する所 |
|---|---|---|
| `template/背景.pptx` | 背景スライド 1 枚（スライドの大きさ・スライドマスタ・レイアウト・フォント。写真の背景のときは背景そのもの） | 全部のスライド |
| `template/背景.json` | 3 つの色：背景色・基本色・強調色（§2.2） | 全部のスライド |
| `template/部品/<部品名>.pptx` | 部品 1 つ（スライド 1 枚以上）。**中身（図形と目印）だけを使う** | その部品を使う式順の行だけ |
| `template/式順/<礼拝>.json` | 礼拝ごとの並びと、各行に入れる曲・聖句。礼拝は `worship`（主日礼拝）・`afternoon`（午後礼拝）・`wednesday`（水曜祈祷会）・`other`（その他） | その礼拝だけ |
| `hymns/<番号>.pptx`・`readings/<番号>.pptx`（いまのまま） | 歌詞・交読文 | その曲・その交読文だけ |

使わなくなるもの: `template/worship.pptx`、`template/verse-spTree.xml`（聖句の見た目は部品「聖句」に移る）。

### 1.2 出来上がりのスライドの作り方

**出来上がりのスライドはすべて「背景スライド ＋ 中身」**。中身は部品のスライドの図形、または歌詞・交読文のスライドの図形。部品・歌詞・交読文のファイルが持っている背景・スライドマスタは使わない。
色は `背景.json` で決める: 背景は背景色の単色（背景色が `null` なら背景.pptx の背景のまま）、中身の文字は白・黒・色なし → 基本色、黄 → 強調色に置き換える（§2.3）。
（歌詞・交読文はこれまでもこの方法で入れていた。部品も同じ扱いにする。）

### 1.3 プログラムの分け方（それぞれ単独で試験する）

| 段 | 受け持つこと | 知らないこと |
|---|---|---|
| ① 値 | 週のデータ・マスタ・聖書から、礼拝ごとの値の表を作る（「名前 肩書」、聖句を節ごとに分ける、曲名を引く、など） | pptx |
| ② 部品の展開 | 部品 1 つと値から、スライドの中身を作る（目印を埋める、繰り返しを複製する、場所を歌詞・交読文に置き換える、値が無ければ飛ばす） | 並び・背景 |
| ③ 組み立て | 中身を 1 枚ずつ背景スライドに載せて pptx にする（背景色を付ける、文字の色を役で置き換える、画像の取り込み、式順の行ごとのセクション） | 目印・データ |
| ④ 式順 | 式順の JSON を読み、行ごとに ② を呼び、③ に渡す | 値の作り方・背景 |
| ⑤ 確かめ | §6 の確かめ。作るときと、テンプレを差し替えるときの両方で使う | — |

値の作り方を直しても ②③ は変わらない。背景の扱いを直しても ①② は変わらない。

コード（`src/lib/slides/`）: ① `values.mjs`（表の名前は `vocab.mjs`）・② `fill.mjs`・③ `assemble.mjs`・④ `build.mjs`（`buildSlides`）・⑤ `check.mjs`、pptx の読み書き `pptx.mjs`。入口は `src/lib/slides.mjs`（画面が読む）。試験は `tests/slides-*.test.mjs`。検証用の CLI は `scripts/make-slides.mjs`。

## 2. 背景と色（`template/背景.pptx`・`template/背景.json`）

### 2.1 背景.pptx

- スライドは **1 枚だけ**。全部のスライドの土台になる（スライドの大きさ、スライドマスタ・レイアウト、配色のフォント）。
- 背景の色は `背景.json` の背景色で決める（§2.2）。背景色が `null` のときだけ、このスライドの背景（背景の書式、またはスライドマスタの背景）をそのまま使う。写真の背景（季節の背景など）はこちら。
- 背景スライドに図形（ロゴなど）を置くと、全部のスライドの**奥**に出る（部品の図形はその上に重なる）。
- 部品のプレースホルダー（「タイトル」「本文」の枠）の文字の書式は、背景スライドのレイアウトから受け継ぐ。**部品は背景.pptx を写して作る**と、PowerPoint で見る姿と出来上がりが同じになる（いまの部品は、背景スライドと同じ「Title and Content」のレイアウトで、配色のフォントも同じ。2026-10-24 確認）。
- 部品ごとに別の背景（写真）を使う機能は、いまは持たない（要るようになったら、背景.pptx の中にセクションで名前を付けた背景スライドを並べ、式順の行で選ぶ形に広げる。スライドマスタが 1 つのファイルに収まるので、組み立ては変わらない）。背景色だけなら、式順の行に `"背景色"` を足す形ですぐ広げられる（スライドごとに単色の背景を付けるだけなので）。

### 2.2 背景.json

```json
{ "背景色": "0000FF", "文字色": { "基本": "FFFFFF", "強調": "FFFF00" } }
```

| 項目 | 意味 | 値 |
|---|---|---|
| `背景色` | 全部のスライドの背景の色（スライドの背景に単色を付ける。スライドマスタの背景より優先） | 6 桁の色コード（先頭の `#` はあってもよい）。`null` なら背景.pptx の背景のまま |
| `文字色.基本` | ふつうの文字の色（§2.3） | 6 桁の色コード |
| `文字色.強調` | 強調の文字の色（§2.3） | 6 桁の色コード |

- いまの値（見本）は背景色 `0000FF`（青）・基本 `FFFFFF`（白）・強調 `FFFF00`（黄）。これまでの出来上がりと同じ色。
- 季節などで替えるときは、背景.json（と、写真なら背景.pptx）を差し替える。明るい背景には暗い文字色を選ぶ（例: 背景色 `FFF8E7`・基本 `2B2B2B`・強調 `C2185B`）。写真の背景で文字が読みにくいときは、文字色を替えるか、背景スライドの写真の上に半透明の四角を重ねる。

### 2.3 文字の色の役

部品・歌詞・交読文のファイルの文字は、**白（ふつう）と黄（強調）の 2 色で作る**約束にし、出来上がりで `背景.json` の色に置き換える。元のファイルは変えない。

| 元の文字の色 | 出来上がり |
|---|---|
| 白（固定の `FFFFFF`、テーマの色「背景 1」など） | 基本色 |
| 黒（`000000`、テーマの色「テキスト 1」など） | 基本色 |
| 色の指定が無い文字（スライドマスタの色を受け継ぐもの） | 基本色 |
| 黄（`FFFF00`） | 強調色 |
| そのほかの色 | そのまま |

- 黄（強調）を使っているのは、部品「聖句」の出典（書名・章・節）と、交読文の一方の声（交読文 64 個すべて）。歌詞には無い（2026-10-24 確認）。
- 明るさ・透明度などの調整は残す（色だけ置き換える）。
- そのほかの色は歌詞 268（アクセントの色）と交読文 76（赤）だけ（2026-10-24 確認）。
- この決まりで、いまの生成では青地に黒い文字で出ている歌詞 9 個（188 は黒、233・275・357・375・440・483・518・544 は色の指定なし）も基本色で出るようになる。
- 交読文のファイル自身の背景は濃紺（`000099`、64 個中 62 個）だが、いまも出来上がりでは使っていない（共通の背景に載る）。

## 3. 部品（`template/部品/<部品名>.pptx`）

### 3.1 決まり

1. **部品のファイルの中身（図形）だけを使う。** ファイルの背景・スライドマスタは使わない（§2）。文字は白と黄で作る（§2.3）。
2. **変わる所は、すべて目印 `{{名前}}` で書く。** 目印以外の文字・図形・書式には、コードは触れない（文字の色だけは §2.3 の役で置き換える）。目印の名前は §5 の表にあるものだけ。
3. **目印は 1 つの書式で書く**（目印の途中で大きさや色を変えない）。入れた文字は目印の最初の文字の書式になる。目印の前後の文字の書式はそのまま残る。
4. **改行を含む値**（報告の本文など）は、その段落を行の数だけ同じ書式で分ける。目印の前にある文字（「1.　」など）は 1 行目にだけ付く。
5. 部品名に使える字: 日本語・英数字・`-`・`_`（スペースと `/ \ : * ? " < > |` は使わない）。部品名は式順から呼ぶ名前になる。

### 3.2 スライドの種類（目印で決まる）

| 種類 | 見分け方 | 出来上がり |
|---|---|---|
| ふつう | 下の 2 つ以外 | 目印を値で置き換えた 1 枚 |
| **場所** | `{{曲.歌詞}}` か `{{交読文}}` があるスライド | そのスライドが、歌詞（歌詞ファイルの 2 枚目以降）または交読文（交読文ファイルの全部。題のスライドも）の中身に丸ごと置き換わる（0 枚以上）。場所のスライドに書いたほかの文字（説明など）は出ない |
| **繰り返し** | `{{聖句.…}}` か `{{報告.…}}` があるスライド | 項目の数だけ複製して、それぞれの値で埋める。0 個なら出ない |

## 4. 式順（`template/式順/<礼拝>.json`）

```json
{
  "式順": [
    {"部品": "準備賛美", "曲": "準備賛美"},
    {"部品": "主日礼拝"},
    {"部品": "聖句", "聖句": "招詞"}
  ]
}
```

- 行は上から順に出来上がりの並びになる。同じ部品を何度使ってもよい（黙祷を最初と最後に、など）。
- 行に書けるのは 3 つだけ: `"部品"`（必ず）、`"曲"`（部品に曲の目印があるとき必ず。値の名前は §5.2）、`"聖句"`（部品に聖句の目印があるとき必ず。§5.3）。
- **週報の式順（`config.json` と週ごとの式順）とは別物。** スライドには紙面に刷らないもの（準備賛美、使徒信条の本文、報告の本文、最後の黙祷）があり、並びも違ってよい（献金と賛美 3 など）。週ごとに変わるのは「あるかないか」だけ（聖餐式。§5.4）。

見本（`out/template/式順/`）:
- `worship.json`: 準備賛美 → 主日礼拝 → 黙祷 → 招詞 → 聖句(招詞) → 司会者祈祷 → 賛美(賛美1) → 使徒信条 → 交読文 → 祈祷 → 賛美(賛美2) → 聖書朗読 → 聖句(聖書朗読) → 説教 → 聖句(引用聖句) → 聖餐式 → 献金 → 賛美(賛美3) → 献金祈祷 → 報告 → 報告本文 → ご年配 → 頌栄 → 祝祷 → 黙祷（10/24 の組み立て見本 `worship.pptx` の並び）
- `afternoon.json`: 聖句(聖書朗読) → 説教 → 聖句(引用聖句) → 賛美(賛美)（いまの並び）
- `wednesday.json`: 賛美(賛美1) → 聖句(聖書朗読) → 説教 → 聖句(引用聖句) → 賛美(賛美2)（いまの並び）
- `other.json`: 聖句(引用聖句)

### 5.2 曲（`"曲"` の値）

| 礼拝 | 値 | 出どころ |
|---|---|---|
| 主日礼拝 | `準備賛美` | 作る直前に画面で入れる番号（保存しない。ARCHITECTURE.md §18） |

| | `聖餐式` | 週の式順（`morning.program`）の `{ preset: '聖餐式', hymn }`。式順に無い週は「なし」 |
| 午後礼拝 | `賛美` | `afternoon.hymn` |
| 水曜祈祷会 | `賛美1`・`賛美2` | `wednesday.hymns[0]`・`[1]` |

`{{曲.番号}}` は番号、`{{曲.曲名}}` は曲名マスタの題、`{{曲.歌詞}}`（場所）は歌詞ファイル `hymns/<番号>.pptx` の 2 枚目以降（1 枚目は歌詞ファイルの題のスライドで、題は部品が受け持つ）。

### 5.3 聖句（`"聖句"` の値）

| 礼拝 | 値 | 出どころ |
|---|---|---|
| 主日礼拝 | `招詞` | `morning.call_to_worship` |
| | `聖書朗読` | `morning.scripture.ref` |
| | `引用聖句` | `slides.sermon_refs`（上から順） |
| 午後礼拝 | `聖書朗読`・`引用聖句` | `afternoon.scripture`・`slides.afternoon_refs` |
| 水曜祈祷会 | `聖書朗読`・`引用聖句` | `wednesday.scripture.ref`・`slides.wednesday_refs` |
| その他 | `引用聖句` | `slides.other_refs` |

- 1 節 1 枚。短い節は 70 字までまとめる（詩篇の表題＝0 節は 1 枚に分ける）。
- `{{聖句.書名}}` は書名（`マタイの福音書`）、`{{聖句.章}}` は `5章`（詩篇は `90篇`）、`{{聖句.節}}` は `3節`／`3～5節`（詩篇の表題は空）。単位は値に含む。
- 本文の字の大きさは、部品の大きさを 70 字までの大きさとして、110 字・160 字・それ以上で 1 段ずつ縮める（いまの 54→44→36→32pt と同じ）。出典は部品の大きさのまま。

### 5.4 値が無いとき

| 状態 | 出来上がり |
|---|---|
| 曲が「なし」（聖餐式が週の式順に無い） | その行の部品を丸ごと飛ばす |
| 曲の番号が空（準備賛美も） | 題のスライドは番号・曲名を空欄で残し、歌詞は 0 枚（午後・水曜も同じ。これまでの午後・水曜は、番号が空なら賛美のスライドを出さなかった） |
| 歌詞・交読文のファイルが無い | その場所は 0 枚＋注意 |
| 聖句の箇所が空 | 0 枚（読めないときは注意） |
| 交読文の番号が空・報告が無い | 0 枚 |
| 祈りの対象の見出しも名前も空 | その行の部品を丸ごと飛ばす |
| そのほかの目印の値が空 | 空の文字が入る |

## 7. 出来上がりの pptx

- ファイル名はいまのまま（`<日付>.pptx`、`<日付>-午後礼拝.pptx`、`<水曜の日付>-水曜祈祷会.pptx`、`<日付>-その他.pptx`）。
- **式順の行ごとにセクションを付ける**（名前は部品名、曲・聖句があれば `賛美（賛美2）`・`聖句（引用聖句）`）。担当者が PowerPoint で探しやすくする。
- 午後・水曜の賛美の題は、これまでの「歌詞ファイルの題のスライド」から、部品「賛美」の題のスライドに変わる（主日礼拝と見た目がそろう）。
- 主日礼拝に、招詞の後の「招詞の箇所の本文」（聖句(招詞)）が新しく入る（組み立て見本のとおり）。
- 背景と文字の色は `背景.json` の 3 色になる（いまの値ならこれまでと同じ色。§2.3 の歌詞 9 個は黒から白に）。

## 8. 週報への影響

- 作り直すのはスライドを作る部分だけ。週報の入力・保存・PDF（紙面）・サイトへの反映には影響しない（生成コード `src/lib/slides.mjs` を使うのはスライド作成のボタンの部品・検証用の CLI・試験だけ。紙面は `src/template/` で別物。週データの形も週報の式順も変えない）。
- 週報 Worker 側で触ったのは、テンプレのファイルの出し入れだけ: キーの決まり（`src/lib/file-keys.mjs`。API `src/lib/api.mjs` と担当者の窓口 `src/lib/slides-window.mjs` が同じものを見る。日本語のパスは戻してから比べる）、一覧 `GET api/templates`、マスタの「テンプレ」（`src/ui/templates.mjs`）。「ファイルの差し替え」（`src/ui/replace.mjs`）は JSON だけになった。同期・recovery はフォルダの入れ子に対応済み。

## 9. 切り替えの手順

1. （済み）見本（`out/template/` の `背景.pptx`・`背景.json`・`部品/`・`式順/`）をユーザーが確認した。`組み立て確認/` は、式順のとおりに部品を背景に載せただけ（目印はそのまま）の確認用。`3色の試し（…）.pptx` は、背景色と文字色を置き換えた試し（主日礼拝の部品に、歌詞 101・233 と交読文 1 の実物を足したもの）。
2. （済み、`gen-1`）生成コードを ①〜⑤ に作り替え、古い目印・見出しで探す処理・空きスロット・`verse-spTree.xml` を読む処理をすべて消した。試験と手元の両方の画面で確かめた。
3. 新しいファイルはいまと別のキーなので、**先に本番へ上げても、いまのコードには影響しない**。`gen-1` を preview に載せる → preview のマスタの「テンプレ」から一式を上げる（本番の KV に入る）→ preview で 4 エリアとも作って確かめる → main に反映 → 本番で確かめる → 管理画面の「使わなくなったファイル」で `template/worship.pptx`・`template/verse-spTree.xml` を消す → `src/lib/file-keys.mjs` から外す。
4. この文書を「実施済み」にし、ARCHITECTURE.md §18・docs/OPERATIONS.md をこの文書へのリンクに置き換える。

## 10. 決めたこと（2026-10-24）

- 部品は**別ファイル**、背景は**背景スライド 1 枚**にそろえる（ユーザー提案。影響範囲を閉じるため。いちど「1 つの pptx をセクションで分ける」案を出したが、背景を分ければ部品ごとのスライドマスタの違いは問題にならないので取り下げた）。
- 曲と聖句の目印は汎用（`{{曲.…}}`・`{{聖句.…}}`）にし、どれを入れるかは式順の行で決める（賛美 1〜3 の部品は 1 つにまとめる）。
- 司会者祈祷は、招詞（と招詞の聖句）の後。文字は固定。
- 準備賛美が空なら、題を空欄で残す（歌詞は入れない）。
- 祝祷は週のデータから。頌栄はテンプレに固定（変えるときは設定 `config.json` の `doxology` とテンプレの両方）。
- **祈りの対象の名前は週のデータから**（見出しと同じ）。週報の報告にも同じ名前が週のデータから刷られるので、スライドだけマスタにすると正本が 2 つになり食い違いうる。マスタの利点（一度直せば以後ずっと）は、毎週の引き継ぎで得られている。将来マスタに移すときは、週報とスライドを一緒に移す。
- **背景色・基本色・強調色の 3 つは `背景.json` の色コードで決める**（ユーザー提案）。背景色が `null` なら背景.pptx の背景のまま（写真用）。部品・歌詞・交読文の文字は白と黄で作り、出来上がりで置き換える（§2.3）。式順ごとには持たない（背景と文字の色は組で、4 つの礼拝で共通のため）。
- 牧師連絡先のスライドは置かない（10/24 のユーザーの編集で外れた）。
- 前奏・後奏・黙想の部品は、式順で使っていなくても置いておく（いつでも式順に足せるように）。

## 11. 確認したい点（ユーザー）
